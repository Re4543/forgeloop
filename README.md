# ForgeLoop

> A self-built coding agent harness: the engineering layer that turns an LLM's "next-step ideas" into a system that can reliably read/write code, run tests, and self-correct — with governance guardrails, HITL approval, and a deterministic feedback loop.
>
> AI4SE 期末项目 A · Coding Agent Harness。核心等式：**Agent = LLM + Harness**，本项目交付 Harness 这一层。

## 项目简介

ForgeLoop 是一个自研的 Coding Agent Harness。它把"只会决定下一步做什么"的 LLM 封装成能稳定读写代码、执行命令、跑测试并自我修正的系统。六个维度（决策封装 / 动作工具 / 上下文与记忆 / 治理护栏 / 反馈闭环 / 声明式配置）都有可运行的最低实现，其中**治理护栏**是 main contribution。

**核心特性：**
- 自研 agent 主循环（不依赖任何 agent SDK）
- 可注入的 LLM 抽象层（OpenAI 兼容，支持 DeepSeek/OpenAI/Qwen/Kimi 等）
- 自定义 JSON-in-text 动作协议（不使用 function-calling，解析可独立单测）
- 护栏规则引擎 + HITL 审批状态机 + 路径范围围栏
- 确定性反馈闭环（pytest 输出解析 → 失败分类 → 回灌上下文）
- 跨会话记忆持久化（SQLite + 关键词检索）
- FastAPI WebUI（轨迹展示 + HITL 审批队列）
- Docker 分发 + GitLab CI / GitHub Actions

## 安装

### 从 Release 安装（推荐）

```bash
pip install https://github.com/Re4543/forgeloop/releases/download/v0.1.0/forgeloop-0.1.0-py3-none-any.whl
```

### 从源码安装

```bash
git clone https://github.com/Re4543/forgeloop.git
cd forgeloop
pip install -e ".[dev]"
```

### 从 Docker 安装

```bash
docker build -t forgeloop .
```

## 运行

### 本地运行（CLI + WebUI）

```bash
# 1. 配置 API key（存储在 OS 钥匙串，不进 Git）
forgeloop key set
# 输入 API key（隐藏输入）

# 2. 查看 key 状态
forgeloop key status
# Provider: openai
# Status: configured
# Last 4 chars: abcd

# 3. 创建 forgeloop.yaml 配置文件
cat > forgeloop.yaml << 'EOF'
workspace_root: .
llm:
  model: deepseek-chat
  base_url: https://api.deepseek.com/v1
server:
  host: 127.0.0.1
  port: 8000
  secret: ""  # 留空则自动生成 64 字符随机密钥
agent:
  max_rounds: 50
  parse_fail_limit: 3
  approval_timeout_seconds: 86400
EOF

# 4. 启动 agent + WebUI
forgeloop run --task "fix the failing tests"

# 输出：
# WebUI: http://127.0.0.1:8000
# Secret: <auto-generated-64-char-secret>
```

### Docker 运行

```bash
# 启动 WebUI（无 agent loop，用于查看/审批已有会话）
docker run -p 8000:8000 \
  -v $(pwd)/workspace:/home/forgeloop/workspace \
  -e OPENAI_API_KEY=sk-xxxx \
  forgeloop

# 启动 agent + WebUI
docker run -p 8000:8000 \
  -v $(pwd)/workspace:/home/forgeloop/workspace \
  -e OPENAI_API_KEY=sk-xxxx \
  forgeloop run --task "fix the failing tests" --workspace /home/forgeloop/workspace
```

### 其他命令

```bash
# 仅启动 WebUI（不运行 agent loop）
forgeloop serve

# 恢复有待审批的会话
forgeloop resume <session-id>

# 清除 API key
forgeloop key clear
```

## 安全边界说明

### 凭据威胁模型与对策

| 威胁面 | 威胁 | 对策 |
|--------|------|------|
| 源码 | API key 硬编码 | key 不进源码；`.env` 在 `.gitignore` 中 |
| Git 历史 | key 被提交 | `git log -p \| grep -i "sk-"` 交付前自查 |
| 日志 | key 出现在日志 | `redact()` 对 `sk-*` 模式打码；全局异常处理器调用 |
| 进程环境 | `OPENAI_API_KEY` 环境变量 | 作为 keyring 的降级来源，README 警告明文风险 |
| WebUI 回显 | key 出现在 API 响应 | `/credentials` 端点只返回 `configured + last_four`，不回显明文 |
| Shell history | key 出现在命令行 | `forgeloop key set` 使用 `getpass`（隐藏输入） |

### Key 在目标机的安全配置

**推荐方式（keyring）：**
```bash
forgeloop key set    # 隐藏输入，存储在 OS 钥匙串
```

**降级方式（环境变量）：**
```bash
export OPENAI_API_KEY=sk-xxxx    # 明文，有风险
```

**Docker 中注入 key：**
```bash
# 方式 1：环境变量（明文，适合 CI/临时）
docker run -e OPENAI_API_KEY=sk-xxxx forgeloop

# 方式 2：挂载 .env 文件（明文文件，需保护）
docker run -v $(pwd)/.env:/home/forgeloop/.env forgeloop
```

## 机制演示

```bash
py -3.13 demo/mechanism_demo.py
```

三场景确定性复现（mock LLM，零网络）：

1. **护栏拦截危险动作**：mock 产出 `rm -rf /` 和越界写入 → Deny/拦截、动作未执行、事件已记录
2. **反馈回灌改变下一步**：写入失败测试 → 校验器解析失败并回灌 → 修复 → 测试转绿 → COMPLETED
3. **HITL 状态机流转**：RequireApproval → 批准执行 / 拒绝丢弃 → COMPLETED

## 已知限制

- **平台**：在 Windows 上开发测试；Linux/macOS 应可运行但未全面测试
- **Python 版本**：要求 3.12+（使用 `py -3.13` 运行测试，系统 Python 3.10 不兼容）
- **LLM 供应商**：仅支持 OpenAI 兼容 API（DeepSeek/OpenAI/Qwen/Kimi/GLM 等）
- **单用户模型**：WebUI 使用共享密钥认证，不支持多用户
- **单会话执行**：当前不支持多会话并发（Plan 3b 规划中）
- **轮询更新**：WebUI 使用 3 秒轮询，非 WebSocket 实时更新（Plan 3b 规划中）
- **凭据管理**：`forgeloop key set/show/clear` 使用 OS keyring；Docker 中需用环境变量
- **路径围栏**：写操作限制在工作区内；读操作允许工作区 + `/tmp/` + `~/.config/forgeloop/`

## 部署架构与 CI/CD

### CI/CD

- **GitLab CI** (`.gitlab-ci.yml`)：
  - `unit-test` job：运行全部 mock-LLM 单测
  - `build-image` job：构建 Docker 镜像并推送到 registry
- **GitHub Actions** (`.github/workflows/ci.yml`)：
  - `unit-test` job：同上
  - `build-image` job：构建并验证 Docker 镜像

### 公网部署

WebUI 可部署到 Fly.io / Render 等平台：

```bash
# Docker 镜像可直接用于部署
docker build -t forgeloop .
docker run -p 8000:8000 -e OPENAI_API_KEY=$SECRET forgeloop serve
```

演示实例可使用 mock LLM（无需 API key），保证公网可演示轨迹与 HITL 审批界面。
